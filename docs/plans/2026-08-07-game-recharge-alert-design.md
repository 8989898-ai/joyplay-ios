# 游戏充值回调弹窗设计

## 目标

游戏页收到 `recharge` 或 `clickRecharge` JS 消息时，展示同一个系统弹窗。玩家选择“通知游戏”后，原生调用 `HttpTool.NativeToJs('recharge')`，通知游戏刷新余额。

## 交互

- 弹窗不设置标题，正文为“请展示APP的充值界面，当玩家充值成功之后，原生调用 JS方法，通知游戏刷新玩家余额”。
- “未充值”只关闭弹窗，不调用 JS。
- “通知游戏”关闭弹窗并调用余额刷新 JS。
- 两个充值消息共用该处理；`newTppClose` 和 `OpenGameSucc` 行为保持不变。

## 实现范围

- 在现有 `GameBridgeScript` 中保存余额刷新脚本，供测试和 `WKWebView.evaluateJavaScript` 共用。
- `GameWebView` 继续统一处理全屏、半屏和 7 分屏的 JS 消息，并通过响应链找到当前宿主控制器展示 `UIAlertController`。
- 不新增充值业务页面，不修改游戏展示模式、关闭流程或现有未提交的背景图改动。

## 验证

- 先增加聚焦测试，断言余额刷新脚本与接入文档一致，并确认测试因缺少脚本而失败。
- 最小实现后确认聚焦测试通过、任务文件通过 `git diff --check`、无签名 Simulator 构建成功。
- 运行时仍需在有效游戏环境中确认两个消息均弹窗、“未充值”不调用 JS、“通知游戏”触发余额刷新。
